# Merchant League Evaluation Harness

This document specifies the Evaluation Mode harness (`TableMode::Eval`) introduced across Wave 2 Card 10 (`PR 1`–`PR 4`), its governing design decisions (`D1`–`D6`), the model-run hold, persisted files, and what is recorded per game and per branched decision.

## Design Decisions (`D1`–`D6`)

| # | Decision | Status |
|---|---|---|
| `D1` | **Three arms:** `off` (`v2_neutral_2026_11_15_r6`), `control` (`v2_control_2026_11_21_r1`), and `on` (`v2_preview_2026_11_20_r2`). | Landed (`off`, `control`, `on`). |
| `D2` | **Duplicate tables:** Deal Turn-1 mandates once using OS entropy, then start every duplicate table from a copy of that table's turn-0 `.save.json` + `.seal` via `EvalHost::fork_duplicate_from_turn_0` / `EvalHost::fork_duplicate_from_game_dir`, which assigns a fresh per-game 32-hex `game_id` (`R5`) and requires turn 0 (`INVALID_TURN_0_CHECKPOINT`). No new secret key, no raw `SealedEvalSeed` on disk; the seal carries the turn-1 deal, including its `deal_seed`, as Club seals do, and the engine's rule against deriving secrets from the public layout seed remains intact. | Landed (`EvalHost` + `fork_duplicate_*` + `game_id`). |
| `D3` | **Control arm wording:** The `control` arm (`v2_control_2026_11_21_r1`, sealed in Row 8 of `ARM_RENDER_PATH_HISTORY`) carries the `on` arm's (`r2`) rules text byte-for-byte; only the tool block and refusal/fixed-reply slots differ (`draft_turn_orders`, `"Returns a fixed reply."`, same input schema as `preview_turn_orders`, returning the bare fixed string `"Draft recorded. Nothing was checked or submitted."` on `role: "tool"` messages with zero rule validation or simulation). | Landed (`league-relay` + `league-eval` `--arm control` and default 3-arm `branch`). |
| `D4` | **Frozen candidate-set regret inputs:** `league-eval` builds **no** regret scorer (that belongs to the report/scoring layer); `decisions/*.json`, `outcome.json`, and `manifest.json` record every input a frozen-set scorer needs: token/timing counts, `tool_calls_used`, `parse_failure`, `refused_market_actions`, `refused_bundle_legs`, `cleared_non_empty_actions`, intermediate preview/draft bundle digests (`intermediate_bundle_sha256s`), prompt token-ID digests (`prompt_token_ids_sha256s`), server-reported `reply_token_ids` and top-5 `reply_top_logprobs`, and `ClubBot::decide_full_turn` (`market_actions`, `pass_b_actions`, `bundle`). | Landed (`league-eval`). |
| `D5` | **First run plan:** `20` seeds × `6` pre-act states (`1` all-`off` `4`-seat game per seed; `2` early, `2` mid, `2` late states per game), each branched three ways (`off`, `control`, `on`) = `120` states, `360` branch runs (`league-eval select`). | Driver landed; GPU runs held pending pre-flight. |
| `D6` | **Table size:** `4` seats only for every Evaluation run, enforced at startup (`INVALID_EVAL_SEAT_COUNT`, exit `1`), with `regent: None` on automated `Model` seats (`ClubBot` seats keep their Club RegentDoctrine). | Enforced (`league-eval` + `EvalHost`). |

## Hold (No Model Runs Before Merge)

**HOLD:** Card 10 builds and verifies on CPU with mock transports only. No model is loaded and nothing runs on a GPU until Card 10 merges, the GPU pre-flight (`10` states run twice in reverse order expecting byte-identical replies) passes, and the Publisher's GPU grant authorizes `D5`.

## Implemented in PR 1: `EvalHost` (`crates/league-core/src/eval/host.rs`)

`EvalHost` owns `TurnEngine` strictly for `TableMode::Eval` (`TableMode::Club` and `TableMode::Game` are refused with `INVALID_TABLE_MODE`). On initialization (`EvalHost::new`), all `32` `EvalVrf` proofs and `32` turns of Phase-2 reveal salts are pre-derived and the raw `SealedEvalSeed` and ephemeral salt root entropy are dropped in memory. Seat modules read solely through `EvalHost::observe_seat` (`SeatObservation`) and `EvalHost::public_receipts` (`PublicSweepReceipt`).

### Persisted Files (`PR 1` + `PR 2`)

Written atomically (`*.tmp` + `flush` + `sync_all` + `rename` in `EvalHost`; `*.tmp` + `flush` + `rename` in `league-eval`):

- `eval-<id>.save.json` — Public, spectator-safe `EvalSaveSnapshot` (`format_version`, `layout_seed` via `ReplayLayoutSeed`, `table_id`, `turn`, `phase`, `cancel_locked`, officers, `PublicTableSpec`, `parities`, `seats`, market/contract books, `eval_vrf_pubkey`, `public_receipts`). Never stores `SealedEvalSeed`, VRF proofs, dealt mandate commitments, mandate reveals, reveal salts, or `bot_tie_seed`. `league-eval` writes strictly through `EvalHost::write_game_save_and_seal` (`R8`).
- `eval-<id>.seal` — Private `EvalSealPayload` (`format_version`, `game_id`, `layout_seed`, `32` pre-derived `vrf_proofs`, serialized `TurnEngine`, `sealed_mandate_deal`, `mandate_commits`, `mandate_reveals`, `logged_turns`, in-progress turn state, `bot_tie_seed`, `live_state_digests`, `turn_salts`, `recorded_act_submissions`, and `pre_act_checkpoint_sha256`). Stores no raw `SealedEvalSeed` on disk; the seal carries the turn-1 deal, including its `deal_seed`, as Club seals do. Both `turn_reveal_salt` and `recorded_act_submissions` stay non-`pub` (`R4`), and recorded-act seals bind strictly to the active `(game_id, table_id, turn, pre_act_checkpoint_sha256)` (`R5`).
- `checkpoints/day-DD-pre-act.save.json` + `checkpoints/day-DD-pre-act.seal` — Written by `EvalHost::write_pre_act_checkpoint` inside `league-eval play` **after** `talk` / writing `negotiation.json` and **before** observing/rendering `to-seat/day-DD-act-*` or collecting any `act` reply (`R9` timing enforced; `TalkAndMarket`, `!cancel_locked`, zero applied actions).
- `checkpoints/day-DD-act-recorded.seal` — Written by `EvalHost::write_act_recorded_seal` after `EvalHost::apply_act_submissions` commits and reveals all seats' `EvalActSubmission`s (`market_actions`, `pass_b_actions`, `bundle`) and before `EvalHost::sweep_turn`. Loading a `day-DD-pre-act` checkpoint via `EvalHost::fork_from_checkpoint` and applying `day-DD-act-recorded.seal` via `EvalHost::apply_recorded_act_submissions_from_seal` / `read_recorded_act_submissions` yields a `PublicSweepReceipt` byte-identical to the original sweep.

Game and checkpoint directories hold sealed game values (mandates, salts, proofs, and act submissions) and must not be committed or published. Branch `--out` directories never receive `.seal` files, peer mandates, salts, VRF proofs, or peer recorded act submissions (`Item 15`). Focal prompt artifacts under `--out` (`to-seat/day-DD-act-<Guild>.md` and `relay/seats/<Guild>.jsonl`) intentionally hold the focal seat's own `SeatObservation` (including its `own_mandate`); only `receipt.json` and `branch_summary.json` (plus season-close public exports in `--game-dir`) are spectator-public.

## Implemented Commands & Recording (`league-eval`)

- **`league-eval play --game-dir <dir> --seats <seats.json> --wrapper <wrapper.md> --arm <off|control|on> --seed <n> [--serving-manifest <path>] [--table-id <id>] [--turns <1..=32>] [--wrapper-version <ver>] [--memory-mode snapshot|emc|full] [--mock-dir <dir>] [--live --cap-credits <n> | --cap-gpu-secs <n>] [--allow-vm-host <host>]`**
  - Validates 4 seats (`INVALID_EVAL_SEAT_COUNT`, `exit 1`), allows `"file"` backend seats only when `"model": "ClubBot"` (`UNSUPPORTED_FILE_SEAT_MODEL`, `exit 1`), refuses any seat configuring `reasoning.exclude_from_transcript: true` (`EVAL_THINK_STRIPPING_FORBIDDEN`, `exit 1`), and enforces pinned wrapper table `PINNED_WRAPPERS` (`v2_seat_brief_2026_11_21_r3`, SHA-256 `66d5665950b2ef9bad177dbcfbe132912fa99f09c328a40866502dbf16d6a06d`, committed at `crates/league-eval/wrappers/v2_seat_brief_2026_11_21_r3.md`), refusing mismatched versions or superseded hashes (`r1`, `r2`, or unpinned files) with `UNPINNED_WRAPPER` (`exit 1`).
  - Creates Evaluation tables via `EvalHost::from_standard_setup_with_model_seats` so automated `Model` seats (`Local` / `Openrouter`) receive `regent: None` (no Standing Regent takeover or synthetic converter/check execution after consecutive empty/passive turns) while `ClubBot` seats keep their Club Regent; records `seats[].has_regent`, `seat_regents`, and per-turn `turn_regent_audit` (`converted_to_ai`, `regent_acted_seats`) in `manifest.json`, and voids any game with `MODEL_SEAT_REGENT_INTERVENTION` (`voided: true`, `voided_games_by_arm`) if a sweep intervenes on a model seat.
  - Draws a fresh non-zero OS-CSPRNG `bot_tie_seed` sealed inside `.seal`, locks `setup.json` (`game_id`, `wrapper_version`, `wrapper_sha256`, `memory_mode`, `seats_sha256`, `eval_reply_wording_arm`, `relay_wording_arm`, `response_schema_sha256`), verifies all setup fields on resume (`INCOMPATIBLE_EVAL_SETUP`, `exit 1`), refuses partial-turn resume when `from-seat/day-DD-*` already exists (`PARTIAL_TURN_FROM_SEAT_EXISTS`, `exit 1`), writes `manifest.json` after every completed turn and recounts counts from `decisions/*.json` on resume, and writes `receipts/*.json` plus season-close `eval-<table>.replay.json`, `scoreboard.json`, and `metrics.json`.
- **`league-eval branch (--checkpoint <dir>/checkpoints/day-DD-pre-act --seat <guild|0..3> | --list <list.json>) --seats <seats.json> --wrapper <wrapper.md> [--serving-manifest <path>] [--arms off,control,on] --out <dir>`**
  - Defaults `--arms` to `[off, control, on]` when omitted. Requires source `setup.json` (`MISSING_SOURCE_SETUP`), verifies matching `game_id`, `table_id`, `--wrapper`, `--memory-mode`, and `--seats` (`INCOMPATIBLE_EVAL_SETUP`), requires `to-seat/day-DD-act-<Guild>.negotiation.json` (`MISSING_BRANCH_NEGOTIATION`), requires focal pre-act transcript `relay/seats/<Guild>.jsonl` (`MISSING_BRANCH_TRANSCRIPT`, except when every prior model round recorded `no_reply: true`) and pre-act scratchpad `checkpoints/day-DD-pre-act.<Guild>.scratchpad.md` on note-keeping model seats (`MISSING_BRANCH_SCRATCHPAD`), refuses non-empty target arm directories (`BRANCH_ARM_DIR_NOT_EMPTY`) and existing `<out>/branch_summary.json` (`BRANCH_SUMMARY_EXISTS`), records `loaded_history_sha256` per loaded source history file in `decision.json` (always keying pre-act scratchpads by relative `"checkpoints/day-DD-pre-act.<Guild>.scratchpad.md"`), forks independent `EvalHost` state per requested arm, splices the focal seat's decision into fixed peer submissions from `day-DD-act-recorded.seal`, restores focal pre-act transcript prefix and scratchpad snapshot, writes `outcome.json`, `receipt.json`, `decision.json`, and per-arm `manifest.json`, and writes `<out>/branch_summary.json` plus `<out>/manifest.json` (`BranchManifest` including `voided_games_by_arm`).
- **`league-eval select --games <d1,d2,...> --per-game 6 --strata 2,2,2 --selection-seed <n> --out <list.json>`**
  - Filters out `"file"` (`ClubBot`) seats so only automated `"Model"` seats are selected (`NO_MODEL_SEATS_FOR_SELECT` if none exist), deterministically partitions each game's playable checkpoints (`day-DD-pre-act` + `day-DD-act-recorded.seal`) into early/mid/late thirds, and replaces any user home-directory prefix in `game_dir` / `checkpoint_prefix` with `<home>` (expanded automatically by `branch --list`).

### Serving Manifest Startup Andons, Environment Snapshot & Decision Telemetry

- **Serving manifest (`--serving-manifest <path>`):** required whenever any evaluated seat (`play`) or focal seat (`branch`) uses a `Model` backend (`MISSING_SERVING_MANIFEST`, `exit 1`). Validates before creating output directories or sending HTTP requests:
  - `server_settings.parallel_slots == 1` (`PARALLEL_SLOTS_EXCEEDED`);
  - all three `llama-server` prompt-cache layers off (`cache_settings.per_request_cache_prompt == false`, `cache_ram_mib == 0`, `cache_idle_slots == false`, paired with `no_cache_prompt_flag` recording), or `cache_settings.enable_prefix_caching == false` on `vllm` (`PREFIX_CACHE_ENABLED`, recording `determinism_status: "not shown bit-exact"` until verified);
  - non-empty 64-hex `model.sha256` (`MISSING_MODEL_SHA256`), non-empty `machine.gpu_name` (`MISSING_GPU_NAME`), and raw `machine.gpu_uuid` hashed immediately via SHA-256 to `gpu_uuid_sha256` without ever writing the raw UUID to `manifest.json` (`INVALID_GPU_UUID_SHA256`).
  - Records `MetadataProvenance` (`server_reported` vs `operator_supplied`) across engine, model, machine, server, cache, and sampling sections, `crate_git_sha`, all wording/wrapper/schema SHA-256 digests (`wording_digests`), and `serving_env_snapshot` capturing `LLAMA_*`, `CUDA_*`, `GGML_*`, and `VLLM_*` environment variables minus secret-named keys (`KEY`, `TOKEN`, `SECRET`, `PASS`, `AUTH`) with user home directory prefixes replaced by `<home>`.
- **Control arm (`v2_control_2026_11_21_r1`) & Eval-only wire behavior:** enables `--arm control` attaching `draft_turn_orders` (`"Returns a fixed reply."`, returning bare `"Draft recorded. Nothing was checked or submitted."` on accepted `role: "tool"` messages); in Eval mode (`config.eval_mode == true`), both `control` and `on` omit `tools` on the request after call 3 and emit `"cache_prompt": false` on `BackendKind::Local` requests without changing Play-mode request bytes.
- **Per-decision telemetry (`EvalDecisionRecord`):** records summed `prompt_tokens`, `completion_tokens`, `wall_secs`, `tool_calls_used`, `parse_failure`, `refused_market_actions`, `refused_bundle_legs`, `cleared_non_empty_actions`, canonical bundle SHA-256 digests (`intermediate_bundle_sha256s` across accepted `draft_turn_orders` / `preview_turn_orders` calls), server-reported `prompt_token_ids_sha256s`, `reply_token_ids`, top-5 candidate `reply_top_logprobs`, and `ClubBot::decide_full_turn` baselines.

### Reply Contract & Pinned Wording (`v2_eval_reply_2026_11_21_r1`)

- **Seat views (`to-seat/`):** `to-seat/day-DD-<round>-<Guild>.md` is rendered in exact order (`eval_talk_instruction` / `eval_act_instruction`, blank line, `eval_state_intro`, blank line, `serde_json::to_string_pretty` `2`-space pretty JSON of the seat's full `SeatObservation`, newline). For model seats in `--arm on`, `day-DD-act-<Guild>.preview-state.json` holds `PublicPreviewState` — the strict public subset required by `league-relay --preview-tool on` (omitting `own_mandate`, `eval_vrf_pubkey`, forecasts, hints, and duplicate receipts). Every `act` seat receives `day-DD-act-<Guild>.negotiation.json` carrying `eval_batna` plus delivered whispers.
- **Unified reply schema (`v2_eval_reply_2026_11_21_r1` + `r2`):** One schema per game (`messages` max 3, `market_actions`, `bundle`, plus `notes` on note-keeping local seats) accepted by `league-relay`'s `ResponseFormatConfig::from_json_str`.
- **Relay behavior, strict parsing, & refusal codes:** Both `league-eval` (`validate_eval_seats_file`) and `league-relay` (`TurnConfig::with_eval_mode(true)`) refuse `reasoning.exclude_from_transcript: true` at setup with `EVAL_THINK_STRIPPING_FORBIDDEN`. Every `league-eval` `play` and `branch` round sets `TurnConfig::with_eval_mode(true)` (Play mode keeps `eval_mode: false` and remains byte-for-byte unchanged, verified for both `--preview-tool off` and `--preview-tool on` including whole-byte masked `relay/calls.jsonl` checks). In Eval mode, `league-relay` leaves `<think>` blocks unstripped, validates against `response_format`, runs attempt `1` only (the single `harness` re-send is disabled so a failed first attempt ends the round immediately with `NO_REPLY`), and persists raw HTTP reply sidecars (`relay/seats/*.http-reply-round-*`) and discarded reply sidecars (`relay/seats/*.discarded-round-*`) with their SHA-256 digests in `relay/calls.jsonl` across **both** `--arm off` and `--arm on`. `league-eval` reads `relay/calls.jsonl` (`read_round_attempt_diagnostics`, `driver.rs`) and the discarded sidecar into every `Model` `EvalDecisionRecord` (`attempts`, `failed_attempts`, `discarded_reply_path`, `discarded_reply_sha256`, and `raw_reply`), excluding `"RESERVED"` and `"CAP_REACHED"` rows from `attempts` and ignoring reconciled `"RESERVED"` rows when locking `first_failure` onto the first actual failed call attempt so no later attempt or orphan marker masks an earlier refusal. Wrong-round classification (`classify_wrong_round_from_raw_text`, `reply.rs`) runs inside `build_no_reply_record` (`driver.rs`) on **any** first failure that left a discarded reply sidecar — not only schema failures (for example, a `LATE_DISCARDED` `talk` reply carrying `market_actions` or `bundle` orders is coded `TALK_REPLY_HAS_ORDERS`): any JSON `talk` reply with non-empty `market_actions` or `bundle` is coded `TALK_REPLY_HAS_ORDERS`, and any JSON `act` reply with non-empty `messages` is coded `ACT_REPLY_HAS_MESSAGES`, counting toward `WrongPartCounter` (`> 5%` preflight stop line) even when the reply also failed schema or arrived late; only non-wrong-round schema/JSON failures become `REPLY_SCHEMA_INVALID`. On delivered replies, `league-eval` likewise decides wrong-round codes from the raw JSON object before order or message parsing, records `TALK_REPLY_INVALID` for malformed talk replies without orders and `ACT_REPLY_INVALID` for malformed act replies, embeds `MESSAGE_RECIPIENT_INVALID` in every invalid-recipient diagnostic (dropping only the offending message while valid siblings deliver), counts both `play` and `branch` replies (`branch_summary.json`), tracks `WrongPartCounter` (`records.rs`) with separate `delivered_wrong_part_refusals` and `no_reply_wrong_part_refusals` numerators (`wrong_part_rate_delivered = delivered_wrong_part_refusals / delivered_model_replies`, `wrong_part_rate_all_rounds = (delivered_wrong_part_refusals + no_reply_wrong_part_refusals) / total_model_rounds`, refusing any rate above `1.0` with `INVALID_WRONG_PART_RATE` instead of clamping), and records whole-bundle refusals (`RefusedBundleRecord { submitted_bundle, error_code, bad_leg_index: "leg not named" }`, incrementing `refused_bundles`).
