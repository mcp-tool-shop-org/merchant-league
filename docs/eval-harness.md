# Merchant League Evaluation Harness

This document specifies the Evaluation Mode harness (`TableMode::Eval`), its governing design decisions (`D1`–`D8`), the model-run hold, persisted files, and what is recorded per game and per branched decision.

## Hold (No Model Runs Before Merge)

**HOLD:** Card 10 builds and verifies on CPU with mock transports only. No model is loaded and nothing runs on a GPU until Card 10 merges, the GPU pre-flight (`10` states run twice in reverse order expecting byte-identical replies) passes, and the Publisher's GPU grant authorizes `D5`.

## Implemented in PR 1: `EvalHost` (`crates/league-core/src/eval/host.rs`)

`EvalHost` owns `TurnEngine` strictly for `TableMode::Eval` (`TableMode::Club` and `TableMode::Game` are refused with `INVALID_TABLE_MODE`). On initialization (`EvalHost::new`), all `32` `EvalVrf` proofs and `32` turns of Phase-2 reveal salts are pre-derived and the raw `SealedEvalSeed` and ephemeral salt root entropy are dropped in memory. Seat modules read solely through `EvalHost::observe_seat` (`SeatObservation`) and `EvalHost::public_receipts` (`PublicSweepReceipt`).

### Persisted Files (`PR 1` + `PR 2`)

Written atomically (`*.tmp` + `flush` + `sync_all` + `rename` in `EvalHost`; `*.tmp` + `flush` + `rename` in `league-eval`):

- `eval-<id>.save.json` — Public, spectator-safe `EvalSaveSnapshot` (`format_version = 2`, including `game_id` (`32` lowercase hex characters matching `.seal`), `layout_seed` via `ReplayLayoutSeed`, `table_id`, `turn`, `phase`, `cancel_locked`, officers, `PublicTableSpec`, `parities`, `seats`, market/contract books, `eval_vrf_pubkey`, `public_receipts`). Never stores `SealedEvalSeed`, VRF proofs, dealt mandate commitments, mandate reveals, reveal salts, or `bot_tie_seed`. `league-eval` writes strictly through `EvalHost::write_game_save_and_seal` (`R8`).
- `eval-<id>.seal` — Private `EvalSealPayload` (`format_version = 2`, `save_format_version = 2`, `turn`, `game_id`, domain-separated `save_sha256` (`Some(SHA-256("league-core/eval-save/v2|" || save_bytes))` on save/seal pairs; `None` strictly on standalone `day-DD-act-recorded.seal`), `engine_commit` (40 lowercase hex recorded provenance), `layout_seed`, `32` pre-derived `vrf_proofs`, serialized `TurnEngine`, `sealed_mandate_deal`, `mandate_commits`, `mandate_reveals`, `logged_turns`, in-progress turn state, `bot_tie_seed`, `live_state_digests`, `turn_salts`, `recorded_act_submissions`, and `pre_act_checkpoint_sha256`). Stores no raw `SealedEvalSeed` on disk; the seal carries the turn-1 deal, including its `deal_seed`, as Club seals do. Both `turn_reveal_salt` and `recorded_act_submissions` stay non-`pub` (`R4`), and recorded-act seals bind strictly to the active `(game_id, table_id, turn, pre_act_checkpoint_sha256)` (`R5`). Format `v1` checkpoints are refused everywhere fail-closed (`INCOMPATIBLE_ENGINE_OR_SCHEMA_VERSION` / `UnsupportedReplayVersion`; see [`docs/checkpoint-trust.md`](checkpoint-trust.md)).
- `checkpoints/day-DD-pre-act.save.json` + `checkpoints/day-DD-pre-act.seal` — Written by `EvalHost::write_pre_act_checkpoint` inside `league-eval play` **after** `talk` / writing `negotiation.json` and **before** observing/rendering `to-seat/day-DD-act-*` or collecting any `act` reply (`R9` timing enforced; `TalkAndMarket`, `!cancel_locked`, zero applied actions).
- `checkpoints/day-DD-act-recorded.seal` — Written by `EvalHost::write_act_recorded_seal` after `EvalHost::apply_act_submissions` commits and reveals all seats' `EvalActSubmission`s (`market_actions`, `pass_b_actions`, `bundle`) and before `EvalHost::sweep_turn`. Loading a `day-DD-pre-act` checkpoint via `EvalHost::fork_from_checkpoint` and applying `day-DD-act-recorded.seal` via `EvalHost::apply_recorded_act_submissions_from_seal` / `read_recorded_act_submissions` yields a `PublicSweepReceipt` byte-identical to the original sweep.

Game and checkpoint directories hold sealed game values (mandates, salts, proofs, and act submissions) and must not be committed or published. Branch `--out` directories never receive `.seal` files, peer mandates, salts, VRF proofs, or peer recorded act submissions (`Item 15`). Focal prompt artifacts under `--out` (`to-seat/day-DD-act-<Guild>.md` and `relay/seats/<Guild>.jsonl`) intentionally hold the focal seat's own `SeatObservation` (including its `own_mandate`); only `receipt.json` and `branch_summary.json` (plus season-close public exports in `--game-dir`) are spectator-public.

### Reply Contract & Pinned Wording (`v2_eval_reply_2026_11_21_r1`)

- **Seat views (`to-seat/`):** `to-seat/day-DD-<round>-<Guild>.md` is rendered in exact order (`eval_talk_instruction` / `eval_act_instruction`, blank line, `eval_state_intro`, blank line, `serde_json::to_string_pretty` `2`-space pretty JSON of the seat's full `SeatObservation`, newline). - **Unified reply schema (`v2_eval_reply_2026_11_21_r1` + `r2`):** One schema per game (`messages` max 3, `market_actions`, `bundle`, plus `notes` on note-keeping local seats) accepted by `league-relay`'s `ResponseFormatConfig::from_json_str`.
- **Relay behavior, strict parsing, & refusal codes:** Both `league-eval` (`validate_eval_seats_file`) and `league-relay` (`TurnConfig::with_eval_mode(true)`) refuse `reasoning.exclude_from_transcript: true` at setup with `EVAL_THINK_STRIPPING_FORBIDDEN`. In Eval mode, `league-relay` leaves `<think>` blocks unstripped, validates against `response_format`, runs attempt `1` only (the single `harness` re-send is disabled so a failed first attempt ends the round immediately with `NO_REPLY`), and persists raw HTTP reply sidecars (`relay/seats/*.http-reply-round-*`) and discarded reply sidecars (`relay/seats/*.discarded-round-*`) with their SHA-256 digests in `relay/calls.jsonl` across **both** `--arm off` and `--arm on`. `league-eval` reads `relay/calls.jsonl` (`read_round_attempt_diagnostics`, `driver.rs`) and the discarded sidecar into every `Model` `EvalDecisionRecord` (`attempts`, `failed_attempts`, `discarded_reply_path`, `discarded_reply_sha256`, and `raw_reply`), excluding `"RESERVED"` and `"CAP_REACHED"` rows from `attempts` and ignoring reconciled `"RESERVED"` rows when locking `first_failure` onto the first actual failed call attempt so no later attempt or orphan marker masks an earlier refusal.
