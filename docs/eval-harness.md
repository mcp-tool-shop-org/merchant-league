# Merchant League Evaluation Harness

This document specifies the Evaluation Mode harness (`TableMode::Eval`) introduced across Wave 2 Card 10 (`PR 1`–`PR 4`), its governing design decisions (`D1`–`D6`), the model-run hold, persisted files, and what is recorded per game and per branched decision.

## Design Decisions (`D1`–`D6`)

| # | Decision | Status |
|---|---|---|
| `D1` | **Three arms:** `off` (`v2_neutral_2026_11_15_r6`), `control` (`v2_control_2026_11_21_r1`), and `on` (`v2_preview_2026_11_20_r2`). | Landed in Card 7/9 (`off`, `on`); `control` arrives in PR 3. |
| `D2` | **Duplicate tables:** Deal Turn-1 mandates once using OS entropy, then start every duplicate table from a copy of that table's turn-0 `.save.json` + `.seal` via `EvalHost::fork_duplicate_from_turn_0` / `EvalHost::fork_duplicate_from_game_dir`, which assigns a fresh per-game 32-hex `game_id` (`R5`) and requires turn 0 (`INVALID_TURN_0_CHECKPOINT`). No new secret key, no raw `SealedEvalSeed` on disk; the seal carries the turn-1 deal, including its `deal_seed`, as Club seals do, and the engine's rule against deriving secrets from the public layout seed remains intact. | Landed (`EvalHost` PR 1; `fork_duplicate_*` + `game_id` PR 2). |
| `D3` | **Control arm wording:** The `control` arm carries the `on` arm's (`r2`) rules text byte-for-byte; only the tool block and refusal/fixed-reply slots differ (`draft_turn_orders`, same input schema as `preview_turn_orders`, returning a fixed note with zero rule validation or simulation). | Planned (`PR 3`; `--arm control` exits `1` `CONTROL_ARM_NOT_IMPLEMENTED` in PR 2). |
| `D4` | **Frozen candidate-set regret inputs:** Card 10 builds **no** regret scorer (that belongs to Card 11); `league-eval` records every input a frozen-set scorer needs in `decisions/*.json` and `outcome.json`, including `ClubBot::decide_full_turn` (`market_actions`, `pass_b_actions`, `bundle`) beside each arm's submission and `raw_reply`. | Planned (`PR 3`; PR 2 lands decision scaffolding and `ClubBot::decide_full_turn` baseline, while remaining Item 20 fields arrive in PR 3). |
| `D5` | **First run plan:** `20` seeds × `6` pre-act states (`1` all-`off` `4`-seat game per seed; `2` early, `2` mid, `2` late states per game), each branched three ways (`off`, `control`, `on`) = `120` states, `360` branch runs (`league-eval select`). | Driver landed (`PR 2`); run awaits Card 10 merge + GPU grant. |
| `D6` | **Table size:** `4` seats only for every Evaluation run under Card 10, enforced at startup (`INVALID_EVAL_SEAT_COUNT`, exit `1`, `R9`). | Enforced (`league-eval`, `PR 2`). |

## Hold (No Model Runs Before Merge)

**HOLD:** Card 10 builds and verifies on CPU with mock transports only. No model is loaded and nothing runs on a GPU until Card 10 merges, the GPU pre-flight (`10` states run twice in reverse order expecting byte-identical replies) passes, and the Publisher's GPU grant authorizes `D5`.

## Implemented in PR 1: `EvalHost` (`crates/league-core/src/eval/host.rs`)

`EvalHost` owns `TurnEngine` strictly for `TableMode::Eval` (`TableMode::Club` and `TableMode::Game` are refused with `INVALID_TABLE_MODE`). On initialization (`EvalHost::new`), all `32` `EvalVrf` proofs and `32` turns of Phase-2 reveal salts are pre-derived and the raw `SealedEvalSeed` and ephemeral salt root entropy are dropped in memory. Seat modules read solely through `EvalHost::observe_seat` (`SeatObservation`) and `EvalHost::public_receipts` (`PublicSweepReceipt`).

### Persisted Files (`PR 1` + `PR 2`)

Written atomically (`*.tmp` + `flush` + `sync_all` + `rename` in `EvalHost`; `*.tmp` + `flush` + `rename` in `league-eval`):

- `eval-<id>.save.json` — Public, spectator-safe `EvalSaveSnapshot` (`format_version`, `layout_seed` via `ReplayLayoutSeed`, `table_id`, `turn`, `phase`, `cancel_locked`, officers, `PublicTableSpec`, `parities`, `seats`, market/contract books, `eval_vrf_pubkey`, `public_receipts`). Never stores `SealedEvalSeed`, VRF proofs, dealt mandate commitments, mandate reveals, reveal salts, or `bot_tie_seed`. `league-eval` writes strictly through `EvalHost::write_game_save_and_seal` (`R8`).
- `eval-<id>.seal` — Private `EvalSealPayload` (`format_version`, `game_id`, `layout_seed`, `32` pre-derived `vrf_proofs`, serialized `TurnEngine`, `sealed_mandate_deal`, `mandate_commits`, `mandate_reveals`, `logged_turns`, in-progress turn state, `bot_tie_seed`, `live_state_digests`, `turn_salts`, `recorded_act_submissions`, and `pre_act_checkpoint_sha256`). Stores no raw `SealedEvalSeed` on disk; the seal carries the turn-1 deal, including its `deal_seed`, as Club seals do. Both `turn_reveal_salt` and `recorded_act_submissions` stay non-`pub` (`R4`), and recorded-act seals bind strictly to the active `(game_id, table_id, turn, pre_act_checkpoint_sha256)` (`R5`).
- `checkpoints/day-DD-pre-act.save.json` + `checkpoints/day-DD-pre-act.seal` — Written by `EvalHost::write_pre_act_checkpoint` inside `league-eval play` **after** `talk` / writing `negotiation.json` and **before** observing/rendering `to-seat/day-DD-act-*` or collecting any `act` reply (`R9` timing enforced; `TalkAndMarket`, `!cancel_locked`, zero applied actions).
- `checkpoints/day-DD-act-recorded.seal` — Written by `EvalHost::write_act_recorded_seal` after `EvalHost::apply_act_submissions` commits and reveals all seats' `EvalActSubmission`s (`market_actions`, `pass_b_actions`, `bundle`) and before `EvalHost::sweep_turn`. Loading a `day-DD-pre-act` checkpoint via `EvalHost::fork_from_checkpoint` and applying `day-DD-act-recorded.seal` via `EvalHost::apply_recorded_act_submissions_from_seal` / `read_recorded_act_submissions` yields a `PublicSweepReceipt` byte-identical to the original sweep.

Game and checkpoint directories hold sealed game values (mandates, salts, proofs, and act submissions) and must not be committed or published. Branch `--out` directories never receive `.seal` files, peer mandates, salts, VRF proofs, or peer recorded act submissions (`Item 15`). Focal prompt artifacts under `--out` (`to-seat/day-DD-act-<Guild>.md` and `relay/seats/<Guild>.jsonl`) intentionally hold the focal seat's own `SeatObservation` (including its `own_mandate`); only `receipt.json` and `branch_summary.json` (plus season-close public exports in `--game-dir`) are spectator-public.

## Implemented in PR 2: `league-eval` (`crates/league-eval/`)

- **`league-eval play --game-dir <dir> --seats <seats.json> --wrapper <wrapper.md> --arm <off|on> --seed <n> [--table-id <id>] [--turns <1..=32>] [--wrapper-version <ver>] [--memory-mode snapshot|emc|full] [--mock-dir <dir>] [--live --cap-credits <n> | --cap-gpu-secs <n>] [--allow-vm-host <host>]`**
  - Uses `--arm <off|on>` (`--arm` replaces earlier `--preview-tool` flag naming; `--preview-tool` is refused as an unknown flag).
  - Validates 4 seats (`INVALID_EVAL_SEAT_COUNT`, `exit 1`, `D6`), allows `"file"` backend seats only when `"model": "ClubBot"` (`UNSUPPORTED_FILE_SEAT_MODEL`, `exit 1`), and refuses any seat configuring `reasoning.exclude_from_transcript: true` (`EVAL_THINK_STRIPPING_FORBIDDEN`, `exit 1`).
  - Draws a fresh non-zero OS-CSPRNG `bot_tie_seed` sealed inside `.seal`, locks `setup.json` (`game_id`, `wrapper_version`, `wrapper_sha256`, `memory_mode`, `seats_sha256`, `eval_reply_wording_arm`, `relay_wording_arm`, `response_schema_sha256`), verifies all setup fields on resume (`INCOMPATIBLE_EVAL_SETUP`, `exit 1`), refuses partial-turn resume when `from-seat/day-DD-*` already exists (`PARTIAL_TURN_FROM_SEAT_EXISTS`, `exit 1`), writes `manifest.json` (with `PASS_B_LIMIT_STATEMENT`) after every completed turn and recounts `manifest.json` from `decisions/*.json` on resume, and writes `receipts/*.json` plus season-close `eval-<table>.replay.json`, `scoreboard.json`, and `metrics.json`.
- **`league-eval branch (--checkpoint <dir>/checkpoints/day-DD-pre-act --seat <guild|0..3> | --list <list.json>) --seats <seats.json> --wrapper <wrapper.md> --arms off,on --out <dir>`**
  - Requires source `setup.json` (`MISSING_SOURCE_SETUP`), verifies matching `game_id`, `table_id`, `--wrapper`, `--memory-mode`, and `--seats` (`INCOMPATIBLE_EVAL_SETUP`), requires `to-seat/day-DD-act-<Guild>.negotiation.json` (`MISSING_BRANCH_NEGOTIATION`), refuses non-empty target arm directories (`BRANCH_ARM_DIR_NOT_EMPTY`), records `loaded_history_sha256` per loaded source history file in `decision.json`, forks independent `EvalHost` state per requested arm, splices the focal seat's decision into fixed peer submissions from `day-DD-act-recorded.seal`, restores focal pre-act transcript prefix and scratchpad snapshot, writes `outcome.json`, `receipt.json`, and `decision.json` per arm, and writes `<out>/branch_summary.json` counting branch refusals and wrong-part metrics.
- **`league-eval select --games <d1,d2,...> --per-game 6 --strata 2,2,2 --selection-seed <n> --out <list.json>`**
  - Filters out `"file"` (`ClubBot`) seats so only automated `"Model"` seats are selected (`NO_MODEL_SEATS_FOR_SELECT` if none exist), deterministically partitions each game's playable checkpoints (`day-DD-pre-act` + `day-DD-act-recorded.seal`) into early/mid/late thirds, and replaces any user home-directory prefix in `game_dir` / `checkpoint_prefix` with `<home>` (expanded automatically by `branch --list`).

### Reply Contract & Pinned Wording (`v2_eval_reply_2026_11_21_r1`)

- **Seat views (`to-seat/`):** `to-seat/day-DD-<round>-<Guild>.md` is rendered in exact order (`eval_talk_instruction` / `eval_act_instruction`, blank line, `eval_state_intro`, blank line, `serde_json::to_string_pretty` `2`-space pretty JSON of the seat's full `SeatObservation`, newline). For model seats in `--arm on`, `day-DD-act-<Guild>.preview-state.json` holds `PublicPreviewState` — the strict public subset required by `league-relay --preview-tool on` (omitting `own_mandate`, `eval_vrf_pubkey`, forecasts, hints, and duplicate receipts). Every `act` seat receives `day-DD-act-<Guild>.negotiation.json` carrying `eval_batna` plus delivered whispers.
- **Unified reply schema (`v2_eval_reply_2026_11_21_r1` + `r2`):** One schema per game (`messages` max 3, `market_actions`, `bundle`, plus `notes` on note-keeping local seats) accepted by `league-relay`'s `ResponseFormatConfig::from_json_str`.
- **Relay behavior, strict parsing, & refusal codes:** Both `league-eval` (`validate_eval_seats_file`) and `league-relay` (`TurnConfig::with_eval_mode(true)`) refuse `reasoning.exclude_from_transcript: true` at setup with `EVAL_THINK_STRIPPING_FORBIDDEN`. Every `league-eval` `play` and `branch` round sets `TurnConfig::with_eval_mode(true)` (Play mode keeps `eval_mode: false` and remains byte-for-byte unchanged). In Eval mode, `league-relay` leaves `<think>` blocks unstripped, validates against `response_format`, runs attempt `1` only (the single `harness` re-send is disabled so a failed first attempt ends the round immediately with `NO_REPLY`), and persists raw HTTP reply sidecars (`relay/seats/*.http-reply-round-*`) and discarded reply sidecars (`relay/seats/*.discarded-round-*`) with their SHA-256 digests in `relay/calls.jsonl` across **both** `--arm off` and `--arm on`. `league-eval` reads `relay/calls.jsonl` and the discarded sidecar into every `Model` `EvalDecisionRecord` (`attempts`, `failed_attempts`, `discarded_reply_path`, `discarded_reply_sha256`, and `raw_reply`), locking the round's recorded outcome onto the first failed attempt so no later attempt can overwrite an earlier refusal. Before coding a failed attempt as `REPLY_SCHEMA_INVALID`, `league-eval` runs wrong-round classification on the raw reply text: any JSON `talk` reply with non-empty `market_actions` or `bundle` is coded `TALK_REPLY_HAS_ORDERS`, and any JSON `act` reply with non-empty `messages` is coded `ACT_REPLY_HAS_MESSAGES`, counting toward `WrongPartCounter` (`> 5%` preflight stop line) even when the reply also failed the schema; only non-wrong-round schema failures and non-JSON text become `REPLY_SCHEMA_INVALID`. On delivered replies, `league-eval` likewise decides wrong-round codes from the raw JSON object before order or message parsing, records `TALK_REPLY_INVALID` for malformed talk replies without orders and `ACT_REPLY_INVALID` for malformed act replies, embeds `MESSAGE_RECIPIENT_INVALID` in every invalid-recipient diagnostic (dropping only the offending message while valid siblings deliver), counts both `play` and `branch` replies (`branch_summary.json`), tracks `WrongPartCounter` with both denominators (`delivered_model_replies` and `total_model_rounds`), and records whole-bundle refusals (`RefusedBundleRecord { submitted_bundle, error_code, bad_leg_index: "leg not named" }`, incrementing `refused_bundles`).
